## 4. Forensic Reconciliation of the 6,000 vs. 4,800 Record Count

A primary question raised in the audit prompt is why `raw_predictions.csv` and `raw_predictions.jsonl` contain **6,000 records**, whereas the primary comparison table in `final_phase4_research_report.md` (Table 3.1) presents **4 conditions** (`E0`, `E3`, `E1`, `E6_bounded`) comprising $4 \times 1,200 = 4,800$ records.

### Forensic Finding:
1. **Source Code Inspection**:
   In `scripts/run_phase4_domain_evaluation.py`, lines 290–298:
   ```python
   methods = [
       ("E0", "Base Model", ...),
       ("E3", "Preservation Adapter (w=5.0)", ...),
       ("E1", "Full Medoid Consensus (K=6)", ...),
       ("E6_bounded", "Bounded Adaptive Router (K=3)", ...),
       ("E6_enhanced", "Enhanced Bounded Router", ...),
   ]
   ```
   The evaluation script executed **5 distinct experimental conditions** across the 1,200 prompts.
2. **Total Records Generated**:
   $$5 \text{ conditions} \times 1,200 \text{ prompts} = 6,000 \text{ rows}$$
3. **Table Presentation in Final Report**:
   In `final_phase4_research_report.md` Table 3.1, the author chose to present the 4 primary benchmark baselines (`E0`, `E3`, `E1`, `E6_bounded`) to match Phase 3's core comparison. The 5th condition, `E6_enhanced` (1,200 records), was documented in `final_domain_shift_evaluation.md` Table 2 and in `phase4_results_summary.json`.
4. **Behavior of `E6_enhanced` vs `E6_bounded`**:
   Because the enhanced routing policy produced the exact same cluster route decisions (53 fast-path clusters and 147 bounded-verification clusters), `E6_enhanced` yielded predictions identical to `E6_bounded`.
5. **Record Integrity**:
   - `raw_predictions.csv`: Exactly 6,000 rows (1,200 rows per method).
   - `raw_predictions.jsonl`: Exactly 6,000 records.
   - Field mismatch between CSV and JSONL: **0 mismatches** across all 6,000 records.
   - Missing or empty answers: **0**.
   - Duplicates within any method: **0**.
